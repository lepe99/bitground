# 뉴스 아카이브 (Pinecone)

스케줄러가 **매시간** 네이버 뉴스(NAVER API HUB)를 모아 **Gemini 임베딩(`gemini-embedding-2`, 768차원)** 으로 바꿔 **Pinecone**에 쌓는다.
일일 AI 인사이트가 "이 코인의 최근 30일 맥락"을 찾을 때 쓴다 (아래 '인사이트 연결').

## 흐름

```
매시간 (scheduler/service/news_archive.go)
 1. 검색어 8개(가상자산, 암호화폐, 비트코인, 이더리움, 리플, 솔라나, 업비트, 코인 시세)로 최신 기사 50건씩 검색
 2. 최근 48시간 기사 중 가상자산 기사만 남김
    - 제목에 가상자산 단어가 있거나, 요약에 서로 다른 가상자산 단어가 2개 이상
 3. 같은 기사 합치기: id = n-{발행일 KST}-{링크 sha1 16자}
 4. Pinecone에 이미 있는 id는 건너뜀 (다시 임베딩하지 않음)
 5. 새 기사를 `title: {제목} | text: {요약}` 형식으로 임베딩 (gemini-embedding-2는 taskType을 받지 않아 용도를 글 앞에 적는다. 동시 3개, 분당 80회 이하, 실행당 최대 100건)
 6. 업서트 (namespace: news)
0시에는 추가로: 90~96일 전 날짜 접두어(n-YYYYMMDD-)로 목록을 찾아 삭제
```

임베딩에 실패한 기사는 저장되지 않고, 다음 실행에서 "아직 없는 기사"로 다시 시도된다.

### 저장하는 메타데이터

| 키 | 내용 |
|---|---|
| `title` | 기사 제목 |
| `snippet` | 검색 결과 요약 (최대 200자, 기사 본문 아님) |
| `url` | 기사 링크 |
| `source` | 언론사 도메인 |
| `published_at` | 발행 시각 (유닉스 초, 기간 필터용) |
| `published` | 발행 시각 (KST, 표시용) |
| `symbols` | 제목·요약에 나온 코인 (`KRW-BTC` …). 이름은 다른 낱말 속에 든 경우('트리플' 속 '리플')를 빼고, 티커는 3자 이상 대문자 단어만 |
| `query` | 처음 찾은 검색어 |

개인정보는 없다.

## 처음 설정

1. **Pinecone 인덱스를 한 번 만든다.** 요금이 드는 리소스라 코드가 자동으로 만들지 않는다.
   - 이름 `bitground-news`, 차원 **768**, metric **cosine**, 서버리스 (예: AWS `us-east-1`)
   - 차원이 다르면 스케줄러가 시작 시 "인덱스 차원이 임베딩 차원과 다릅니다"로 멈춘다.
2. **스케줄러 환경 변수** (`scheduler/.env`, 운영은 Lambda 환경 변수):

| 변수 | 기본값 | 설명 |
|---|---|---|
| `PINECONE_API_KEY` | (없음) | 없으면 아카이브를 건너뛴다 |
| `PINECONE_INDEX` | `bitground-news` | |
| `NEWS_EMBED_MODEL` | `gemini-embedding-2` | |
| `NEWS_EMBED_DIM` | `768` | 인덱스 차원과 같아야 함 |
| `NEWS_EMBED_RPM` | `80` | 분당 임베딩 요청 상한. 요청 한도(429)에 걸리면 낮춘다 |
| `GEMINI_API_KEY`, `NAVER_NEWS_CLIENT_ID/SECRET` | | 인사이트와 같은 키 |

## 규모와 비용 감

- 첫 실행 이후에는 시간당 새 기사 수십 건 수준.
- 네이버 검색: 시간당 8회 (하루 192회).
- 임베딩: 새 기사 수만큼. 보관 90일 × 하루 수백 건 = 수만 벡터 (768차원).
- 실제 요금은 Pinecone·Gemini 요금제를 확인할 것.

## 인사이트 연결 (daily-insight-v4)

인사이트를 만들 때 대상마다 (`scheduler/service/insight_context.go`):

1. 검색어 = 대상 이름 + 오늘 기사 제목 → `gemini-embedding-2` (`task: search result | query: {검색어}` 형식)
2. Pinecone 검색: 코인은 `symbols`에 그 코인이 있는 기사만, 발행 시각은 **30일 전 ~ 24시간 전** (오늘 기사는 `<news>`로 따로 들어가므로 배경은 그 이전 흐름만)
3. 유사도 0.65 이상, 오늘 기사와 링크·제목이 겹치지 않는 기사 최대 4건 → 프롬프트 `<context>` 블록
4. 모델은 `background`에 지난 흐름 1~2문장을 날짜와 함께 쓴다. 오늘 움직임과 인과로 잇지 않는다 (코드가 인과 표현·인용 누락을 검증)
5. 화면(최신동향 AI 분석)에 '지난 흐름' 칸과 참고 기사의 '지난 흐름' 표시

Pinecone 키가 없거나 검색이 실패하면 배경 없이 만든다. 아카이브를 막 시작하면 24시간보다 오래된 기사가 없어 배경이 비어 있고, 매시간 수집이 하루 넘게 쌓이면 채워진다.

## 다시 임베딩 (모델이나 입력 형식을 바꿨을 때)

예전 벡터와 새 벡터가 섞이면 검색 품질이 고르지 않으므로 한꺼번에 맞춘다. 원문 대신 메타데이터의 제목·요약으로 임베딩하고, id·메타데이터는 그대로 둔다.

```bash
# 먼저 몇 건으로 확인
docker compose --profile app --profile scheduler run --rm -e RUN_HOURLY= -e NEWS_REEMBED=3 scheduler
# 전체 (매시 실행의 임베딩과 겹치지 않게 분당 횟수를 낮춘다)
docker compose --profile app --profile scheduler run --rm -e RUN_HOURLY= -e NEWS_REEMBED=all -e NEWS_EMBED_RPM=60 scheduler
```

- 2026-11-06: gemini-embedding-2가 taskType을 받지 않아 입력 형식을 `title: … | text: …` / `task: search result | query: …`로 바꾸고 전체(약 1,500건)를 다시 임베딩

## 확인할 것

- **네이버 검색 API 이용약관**: 검색 결과(제목·요약·링크)를 저장·재가공해도 되는지 확인. 본문은 저장하지 않는다.
- **개인정보처리방침**: 뉴스만 저장하므로 개인정보 처리 위탁은 아니지만, 외부 서비스 목록에 Pinecone을 적어 두면 투명하다.
