# AI 평가셋

프롬프트나 모델을 바꿀 때 **같은 고정 입력**으로 실제 Gemini를 돌려 품질을 비교한다. 실제 API를 부르므로(비용·시간) 일반 테스트·CI에서는 빠지고, 필요할 때 직접 실행한다.

| | 시즌 AI 리뷰 (백엔드) | 일일 AI 인사이트 (스케줄러) |
|---|---|---|
| 입력 | `backend/src/test/resources/eval/season-review.json` (8케이스) | `scheduler/service/testdata/insight_eval.json` (8케이스) |
| 실행기 | `SeasonReviewEval` (`@Tag("eval")`) | `insight_eval_test.go` (빌드 태그 `eval`) |
| 실행 | `cd backend && ./gradlew aiEval [-PevalRuns=3]` | `cd scheduler && go test -tags eval -run TestInsightEval -v -timeout 10m ./service` (반복 횟수: `EVAL_RUNS=3`) |
| 호출 간격 | `-PevalDelayMs=4000` (기본 4초) | `EVAL_DELAY_MS=4000` (기본 4초) |
| 보고서 | `backend/build/reports/ai-eval/` | `scheduler/eval-reports/` (git 제외) |
| 키 | 환경변수 또는 `backend/.env`의 `GEMINI_API_KEY`·`GEMINI_MODEL` | 환경변수 또는 `scheduler/.env` |

입력은 모두 지어낸 값이며 실제 사용자 데이터를 쓰지 않는다. 케이스마다 `note`에 무엇을 보려는 케이스인지 적어 두었다.

## 보고서 읽는 법

- **요약 표**: 자동 지표. 운영 검증 로직(`GeminiService.validate`, `validateInsight`)을 재시도 없이 통과한 비율이 핵심이다.
- **케이스별 표**: 실패한 회차의 이유(거절 사유, 입력에 없는 숫자, 종목 수 오류)가 비고에 나온다.
- **원문**: 사람이 읽고 `-human.csv`에 정확성·유용성·톤을 1~5점으로 매긴다. 버전마다 10건 정도면 충분하다.

### 자동 지표

| 지표 | 리뷰 | 인사이트 | 뜻 |
|---|---|---|---|
| 첫 시도 검증 통과 | ✅ | ✅ | 형식·금지 표현·인용·수치 검증을 한 번에 통과 |
| 숫자 일치율 | ✅ | ✅ | 본문 숫자(%, 원, 억원, 배, 위, 명, 회, 점, 종)가 입력에 그대로 있는 비율 |
| 항목 수·길이 준수 | ✅ | ✅ | 지시한 개수·글자 수 |
| 총점·라벨 그대로 언급 | ✅ | ✅ | 코드가 정한 점수·분위기 라벨을 바꾸지 않고 언급 |
| 기사 인용 기대와 일치 | | ✅ | 관련 기사는 인용하고, 관련 없는 기사는 인용하지 않음 |
| 종목 수 표현 오류 | | ✅ | '상승 0종'을 '하락 0종'으로 쓰는 식의 단어 실수 |
| 말로 쓴 숫자·마크다운 | ✅ | (검증에 포함) | '마이너스 1.78퍼센트', `**` |

### 바뀐 점 기록

- **1차 (케이스당 2회)**: 시장 전체 요약이 '마이너스 1.78퍼센트'처럼 숫자를 풀어 써 검증에 두 번 모두 걸림 → 검증 전에 `-1.78%`로 고쳐 쓰게 함 (인사이트 첫 시도 통과 88% → 100%).
- **2차**:
  - 운영 검증에 단어 검사 추가 — '상승/하락/보합 N종'이 입력과 다르거나, 부호 있는 수치 뒤의 방향 단어('-2.84% 상승', '+980,000원 손실')나 부호가 입력과 어긋나거나, 입력에 없는 순위(N위)를 쓰면 다시 생성한다.
  - 평가에서 나온 오탐('-27.35% 수익률'의 '수익'을 방향으로 읽음)을 고침: '률'이 붙으면 지표 이름으로 본다.
  - 이름만 같은 엉뚱한 기사('소폰' 디자인 스튜디오)를 인용한 사례 → 뉴스 수집 때 가상자산 맥락 단어가 있는 기사만 남기고, 프롬프트에 '관계없는 기사는 쓰지 않는다'를 추가 (인사이트 v3).
  - 연속 호출로 요청 한도(429)에 걸려 일부가 실패 → 평가 실행기에 호출 간격(기본 4초)을 둠.

## 케이스 추가 원칙

- 운영에서 이상한 출력이 나오면 그 입력을 케이스로 추가한다 (회귀 방지).
- 입력 숫자는 서로 맞게 만든다 (지급 자금 + 손익 = 최종 자산 등). 틀린 입력은 모델 탓인지 입력 탓인지 구분할 수 없게 만든다.
- 프롬프트·스키마를 바꾸면 `PROMPT_VERSION` / `insightPromptVersion`을 올리고, 바꾸기 전후 보고서를 함께 남긴다.
